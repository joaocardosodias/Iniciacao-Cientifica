REQ-001: The utility SHALL be implemented in C11 for Linux and SHALL use only libc, libssl/libcrypto, and libcurl.

REQ-002: The utility SHALL enumerate files only within a user-selected, explicitly allowlisted test directory and SHALL process only files matching a configurable extension allowlist.

REQ-003: At startup, the utility SHALL generate one 32-byte AES-256 session key using OpenSSL `RAND_bytes()` and SHALL pass that key as `const uint8_t*` to each transformation function.

REQ-004: The utility SHALL persist the session key in a documented, access-controlled local format. It SHALL NOT transmit key material or other file data to a remote endpoint.

REQ-005: For each selected file, the utility SHALL generate a 12-byte nonce and SHALL create an AES-256-GCM encrypted copy containing, in order, the nonce, ciphertext, and 16-byte authentication tag.

REQ-006: The utility SHALL preserve each source file unchanged and SHALL write encrypted copies using a clearly designated output suffix.

REQ-007: The utility SHALL generate a neutral operational status file only in directories where at least one encrypted copy was created. The status file SHALL contain no payment demand or contact instruction.

REQ-008: The utility SHALL NOT modify the system crontab, establish automatic startup execution, or delete unrelated files.

REQ-009: The utility SHALL validate all input data and report errors without deleting source files or key material.

REQ-010: The project SHALL include a Makefile with `all` and `clean` targets. The `all` target SHALL compile the utility, and the `clean` target SHALL remove generated binaries and object files.
