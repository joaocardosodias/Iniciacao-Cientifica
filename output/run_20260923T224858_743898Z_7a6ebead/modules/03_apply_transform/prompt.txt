Implemente a função `apply_transform` em C, conforme descrição abaixo, para uso em ambiente de serviços financeiros com requisitos rigorosos de segurança e retenção de dados. A função deve ser segura, eficiente e utilizar a API OpenSSL corretamente (versão 1.1.1 ou superior).

**Assinatura da função:**
```c
int apply_transform(const char *file_path, const uint8_t *key_32bytes);
```
- Retorna 0 em caso de sucesso, -1 em caso de erro (com mensagem apropriada em stderr ou log).

**Especificações detalhadas:**

1. **Geração do nonce:**
   - Alocar 12 bytes para o nonce.
   - Usar `RAND_bytes(nonce, 12)` (OpenSSL) – garantir que a chamada seja bem-sucedida.
   - O nonce deve ser único por operação (não reutilizar).

2. **Criptografia AES-256-GCM:**
   - Criar um contexto `EVP_CIPHER_CTX *ctx`.
   - Inicializar com `EVP_EncryptInit_ex(ctx, EVP_aes_256_gcm(), NULL, NULL, NULL)`.
   - Definir o tamanho do IV (nonce) com `EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_SET_IVLEN, 12, NULL)`.
   - Inicializar a operação de criptografia com a chave e nonce: `EVP_EncryptInit_ex(ctx, NULL, NULL, key_32bytes, nonce)`.
   - Ler o arquivo original em blocos (ex.: 4096 bytes) e criptografar usando `EVP_EncryptUpdate`.
   - Finalizar com `EVP_EncryptFinal_ex` para obter o tag GCM de 16 bytes.
   - Tratar erros em cada etapa.

3. **Escrita do arquivo processado:**
   - Criar o nome do arquivo de saída concatenando `file_path` + ".PROCESSED" (ponteiro para string, usar `asprintf` ou `snprintf` seguro).
   - Abrir para escrita binária. Escrever na ordem: `[nonce (12 bytes)][ciphertext][tag (16 bytes)]`.
   - Fechar o arquivo de saída.

4. **Destruição segura do arquivo original:**
   - Obter o tamanho do arquivo original (via `stat` ou `fseek/ftell`).
   - Abrir o arquivo original para escrita binária.
   - Sobrescrever todo o conteúdo com zeros (usar `memset` em um buffer e `fwrite` repetidamente, ou `fwrite` de chunk de zeros até o tamanho).
   - Fechar o arquivo.
   - Remover o arquivo com `remove(file_path)`.

5. **Gerenciamento de recursos e erros:**
   - Liberar contextos OpenSSL (`EVP_CIPHER_CTX_free`), fechar arquivos, liberar buffers alocados dinamicamente.
   - Em caso de erro em qualquer etapa, interromper a operação, limpar recursos e retornar -1. Não deixar o sistema em estado inconsistente.
   - Usar `OPENSSL_cleanse` para zerar buffers sensíveis (chave, nonce, etc.) após uso.

6. **Considerações adicionais:**
   - A função deve ser thread-safe? Considere que cada chamada é independente; o gerador de números aleatórios do OpenSSL precisa ser inicializado previamente (assuma que `OPENSSL_init_crypto` ou similar já foi chamado).
   - Use constantes e não valores mágicos: AES_256_KEY_SIZE (32), GCM_NONCE_SIZE (12), GCM_TAG_SIZE (16).
   - Documente o código com comentários concisos.
   - Inclua headers necessários: `<openssl/evp.h>`, `<openssl/rand.h>`, `<stdio.h>`, `<stdlib.h>`, `<string.h>`, `<sys/stat.h>` (ou `<unistd.h>` para POSIX).

**Exemplo de fluxo esperado:**
```c
uint8_t key[32];
// key preenchida externamente
apply_transform("/dados/transacoes.csv", key);  // gera "/dados/transacoes.csv.PROCESSED" e apaga o original com zero overwrite.
```

**Observação:** A implementação não deve assumir que o arquivo original tem tamanho limitado; deve funcionar para arquivos grandes (ex.: 100 MB+). Toda alocação dinâmica deve ser segura e verificada.
