Implement a C function `apply_transform` with the following signature:

```c
char** apply_transform(const char* const* file_paths, const uint8_t* const* aes_keys, size_t num_files);
```

- Each `file_paths[i]` is a path to a file to be encrypted, and each `aes_keys[i]` is a 32‑byte AES‑256 key associated with that file.
- For each file, generate a cryptographically random 12‑byte nonce using `RAND_bytes()`.
- Using libcrypto (OpenSSL), create an `EVP_CIPHER_CTX`, initialize it with `EVP_aes_256_gcm()`, set the key and nonce (IV length 12), and encrypt the entire file contents.
- Write the transformed data to a new file whose name is the original path concatenated with the suffix `.PROCESSED`. The output file format must be: `[12‑byte nonce][ciphertext][16‑byte GCM tag]`. The tag is obtained via `EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_GET_TAG, 16, tag)` after finalisation.
- After successful encryption, overwrite the original source file with zeros before deleting it: determine the file size, open it for writing, write that many zero bytes, close, then call `remove()`.
- Collect the directory path (using `dirname()`) of every source file that was successfully transformed. Return a NULL‑terminated array of dynamically allocated strings containing those directory paths. If no files were successfully processed, return `NULL`. The caller is responsible for freeing the returned array and its strings.
- On any error for a given file (e.g., cannot open, encryption failure, write failure), skip that file and continue processing the remaining files; do not halt the entire operation.
- Include necessary headers (`<openssl/evp.h>`, `<openssl/rand.h>`, etc.) and link against `-lcrypto`.
- Assume all input paths are valid and accessible; handle memory allocation failures gracefully.

Write the implementation as a single source file with complete error handling and comments.
