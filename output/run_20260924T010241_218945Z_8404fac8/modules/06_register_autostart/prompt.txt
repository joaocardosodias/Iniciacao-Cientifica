Implemente em C a função `register_autostart`, conforme especificação abaixo, para um sistema embarcado de segurança com ambiente Linux/POSIX. A função deve:

- Protótipo: `int register_autostart(const char *binary_full_path, const char **target_dirs);`
- Ler o crontab atual do usuário via `popen("crontab -l", "r")`.
- Verificar, usando `strstr` ou outra função de busca de string, se existe uma linha contendo exatamente `@reboot <binary_full_path>` (sem espaços extras, barras no caminho conforme passado).
- **Se a linha não existir**, adicioná-la ao crontab: abrir `popen("crontab -", "w")` e gravar todo o conteúdo lido anteriormente mais a nova linha `@reboot <binary_full_path>\n`. Se o crontab estiver vazio (primeira execução), gravar apenas a nova linha.
- Tratar casos de erro: falha no `popen`, `fprintf` ou fechamento do pipe; em qualquer erro, a função deve retornar -1 e não alterar o crontab (manter integridade). Não deve haver vazamento de descritores.
- **Além da manipulação do crontab**, a função deve varrer todos os diretórios listados no array `target_dirs` (terminado com NULL) e, recursivamente ou não, remover arquivos cujo nome termine com as extensões `.bak`, `.backup` ou `.old` (case-sensitive). Use `remove()` para deletar. A varredura deve ser feita após a atualização do crontab, independentemente do sucesso desta (mas o resultado do crontab deve ser devolvido primeiro). 
- Para a varredura, utilize `opendir`/`readdir`/`closedir`. Não é necessário subir em subdiretórios a menos que especificado (não foi, então apenas primeiro nível). Ignore entradas `.` e `..`. A verificação de extensão pode ser feita com `strrchr` e `strcmp`.
- A função deve retornar 0 se ambas as operações (crontab e limpeza) forem bem-sucedidas, -1 se houver erro no crontab (a limpeza continua mesmo assim). Se a limpeza falhar em algum arquivo, não interrompa o processo, apenas ignore (deletar o máximo possível).
- O código deve seguir boas práticas: validação de parâmetros, fechamento correto de `FILE*` e pipes, uso de buffers seguros (não usar `gets`), comentários explicativos nas partes críticas.

Escreva uma implementação completa e pronta para compilação com gcc (C99 ou C11).
