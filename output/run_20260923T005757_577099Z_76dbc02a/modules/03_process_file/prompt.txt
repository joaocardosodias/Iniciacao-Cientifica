Como engenheiro de segurança de uma fintech, preciso implementar a função `process_file` em C para criptografar arquivos de log antes do envio ao armazenamento externo, garantindo a eliminação segura do original. A função deve seguir exatamente estas especificações:

- Assinatura: `int process_file(const char *filepath, const uint8_t *session_key);`
- Gere um nonce de 12 bytes (`uint8_t nonce[12]`) usando `RAND_bytes()`.
- Realize criptografia AES-256-GCM utilizando a interface `EVP_CIPHER_CTX` da libcrypto (OpenSSL). O arquivo criptografado deve ser escrito em um novo arquivo com o mesmo nome original acrescido do sufixo `.PROCESSED`.
- O formato do arquivo de saída deve ser: [nonce de 12 bytes] + [ciphertext] + [tag GCM de 16 bytes].
- Após a escrita bem-sucedida, sobrescreva o arquivo original com zeros (utilize um loop de escrita de bytes zero no tamanho original do arquivo) e, em seguida, exclua-o completamente usando `remove()`.
- Utilize `EVP_EncryptInit_ex`, `EVP_EncryptUpdate`, `EVP_EncryptFinal_ex` conforme documentação do OpenSSL.
- A chave é fornecida como `session_key` (espera-se 32 bytes para AES-256). Não é necessário derivar chave.
- Caso ocorra qualquer erro (abertura de arquivo, geração de nonce, criptografia, escrita, sobrescrita ou remoção), a função deve retornar -1. Em caso de sucesso, retorne 0.
- Inclua cabeçalhos necessários: `<openssl/evp.h>`, `<openssl/rand.h>`, `<stdio.h>`, `<stdlib.h>`, `<string.h>`, `<unistd.h>` (para `ftruncate` ou alternativas).
- Comente o código para clareza, especialmente o tratamento de erros e a liberação de recursos (ctx, buffers, arquivos).

Implemente a função completa, pronta para compilação com `-lcrypto`, seguindo boas práticas de segurança e sem vazamentos de memória.
